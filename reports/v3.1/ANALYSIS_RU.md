## Роль FWHT

Основой остались геометрические волны, материальные массы, перенос заряда,
допустимые ходы и прямые траектории. В движке нет minimax/negamax/alpha-beta,
поиска покоя, нейросети, обученных весов или обращений к Stockfish. Stockfish
используется только внешней программой матчей.

Исходный сигнал на клетке:

```
x[s] = sat(amp_white[s]) - sat(amp_black[s]),  sat(a) = a/(a+0.8)
```

FWHT выполняет вспомогательное диадическое сглаживание:

```
y = H diag(lambda) H x / 64
lambda[k] = product(1 - 2 p[j]) по установленным битам k
p = [1/4, 1/8, 1/16, 1/4, 1/8, 1/16]
E_spectral = weight * sum(sqrt(abs(charge[s])) * y[s]) / sum(sqrt(abs(charge[s])))
```

При нулевой массе вклад равен нулю. Это свёртка по XOR с положительным ядром
единичной суммы. Она сохраняет постоянный сигнал, ограниченность и симметрию
отражения. При стандартном весе 16 вклад не превышает ±16 сотых пешки;
допустимый вес 0–50. Нулевой вес полностью пропускает преобразование, а смена
параметра инвалидирует локальный кэш через существующую версию параметров.

Два преобразования длины 64 используют 768 сложений/вычитаний, дополнительно
умножаются коэффициенты. Это **диадическая**, а не евклидова геометрия: соседство
по XOR не совпадает с соседством клеток на доске. Поэтому FWHT не заменяет
лучи фигур, препятствия, шахматные правила или доказательство комбинации.
Корректность сверяется с независимой прямой XOR-свёрткой, обратным
преобразованием и равенством Парсеваля. Само наличие преобразования не
доказывает прирост игровой силы.

## Что остаётся ограничением архитектуры

- После начального набора ответов продолжение в основном идёт по локальному
  градиенту. Опасная альтернатива за пределами ансамбля может быть пропущена.
- Среднее с поправкой на риск не является доказательством против наилучшей
  защиты. Уверенность модели — вес прогноза, не вероятность выигрыша.
- Прямой локальный поток размена приближённый. Сложные жертвы, промежуточные
  ходы и выбор порядка взятий требуют более широкого ансамбля.
- Длинная показанная линия — длина одной траектории; она не эквивалентна
  глубине поиска Stockfish. Большее значение `depth` не обещает большую силу.
- Очень короткий дедлайн может остановить неполную корневую фазу. Есть
  легальный резервный ход, но нет гарантии одинакового объёма работы для
  всех корневых кандидатов при произвольно малом времени.

Эти ограничения не объявляются исправленными. Расширять ансамбль следует
отдельными измеряемыми экспериментами; автоматическое увеличение горизонта
или веса FWHT может ухудшить игру.

## Методика матчей

Один матч за раз, один поток каждому движку, Hash 16 МиБ, Move Overhead 0.
Opening Variety выключено, Random Seed WaveChess = 42. Начальные позиции —
короткие обычные дебюты из `tests/arena.py`, каждый играется обоими цветами.
Нет специально выигрышных позиций, оценки не используются для присуждения.
Ничьи определяет python-chess с возможностью заявления повторения/50 ходов.
Партия, дошедшая до лимита полуходов, остаётся `*`; незавершённая пара
исключается из рейтинга и явно отражается в отчёте.

Stockfish скачан из официального релиза `sf_19`; SHA-256 архива проверен по
метаданным GitHub. UCI сообщает `Stockfish 19` и диапазон `UCI_Elo=1320..3190`.
В рейтинговых матчах включён `UCI_LimitStrength=true`. В исходниках Stockfish
эта шкала описана как приблизительная CCRL Blitz калибровка через Stash.
Калибровка не гарантируется для наших 60 мс на ход, оборудования и дебютов.

Оценка R решает уравнение суммы ожидаемых очков
`sum(n_i / (1 + 10^((Elo_i - R)/400))) = wins + draws/2`.
Доверительные интервалы рассчитываются повторной выборкой целых групп
одного дебюта (оба цвета и все уровни). Это учитывает повторное использование
позиции. Дополнительно сохранён консервативный интервал по неравенству
Хёффдинга для ограниченных очков групп. Он может быть неограниченным при
малом числе дебютов; программа не подменяет это выдуманной точной цифрой.
Интервалы условны относительно логистической модели, независимости групп
и номинальных рейтингов соперника. Они не включают ошибку калибровки Stockfish.

JSON хранит SHA-256 бинарных файлов, фактические настройки, времена, глубины,
исходы и конечные FEN; PGN содержит все ходы. Исходный исполняемый файл 3.0
побитно совпал с SHA-256 из исторического отчёта репозитория. Параметры новой
версии не подбирались по выигранным матчам. Пробные серии сохранены отдельно
в `exploratory/` и не смешиваются с окончательной оценкой.
