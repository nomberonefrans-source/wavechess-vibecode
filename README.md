# WaveChess 2.2 — волновые траектории

Шахматный движок на Rust без сторонних библиотек и обучения. Доска — решётка зарядов; решение строится из поля влияния, направленного переноса массы и ограниченного набора прямых траекторий. Коэффициенты модели заданы вручную. Это прикладная математическая модель, а не физическое доказательство правильности шахматного хода.

В 2.2 удалены рекурсивный решатель шаховых матов `force.rs`, обратная минимаксная свёртка разменов и оценка угрозы через фиктивный пропуск хода. Нет alpha-beta, negamax, поиска покоя, null-move, killer/history-эвристик и таблицы границ поиска. Убраны отдельные бонусы за пару слонов, открытую вертикаль, седьмую горизонталь, рокировочное расположение, развитие, изолированные и сдвоенные пешки, а также таблица бонусов проходных.

Правила шахмат, массы источников, геометрические потенциалы, легальность ходов, кэш математических оценок и протокол UCI сохранены. Сама генерация и сравнение допустимых ходов необходимы для выбора хода; название «волновой» не означает отсутствия вычисления вариантов вообще.

## Сборка и запуск

Нужен актуальный стабильный Rust. Зависимостей Cargo нет.

```sh
cargo build --release
cargo test
cargo run --release -- selftest
cargo run --release -- play
```

Linux/macOS: `sh build.sh` собирает `dist/wavechess` и запускает самопроверку. В поставке есть проверенный Linux x86-64 бинарный файл `dist/wavechess-linux-x86_64`; при необходимости выполните `chmod +x dist/wavechess-linux-x86_64`.

Windows: `build_windows.bat` собирает `dist/wavechess.exe`, затем `play.bat` запускает игру. Для сборки нужны Rust и C++ Build Tools. Windows-сборка в этой среде не запускалась.

Для Arena, Cute Chess и других оболочек используйте исполняемый файл с аргументом `uci`. При перенаправленном stdin этот режим выбирается автоматически.

## Управление

В консоли вводите `e2e4`, `e7e8q` либо SAN (`Nf3`, `O-O`). `help` показывает все команды. Основные: `go`, `hint`, `moves`, `undo`, `wave`, `memory`, `settings`, `fen`, `setfen`, `time 3`, `depth 16`, `variants 3`.

| Консоль | UCI | Назначение | По умолчанию |
|---|---|---|---|
| `depth N` | `go depth N` | предел распространения цепочки, 1–128 полуходов | 16 |
| `time N` | `go movetime N` | время: секунды в консоли, миллисекунды в UCI | 3 с в консоли |
| `threads N` | `Threads` | рабочие потоки, 1–256 | доступные ядра |
| `cache N` | `Hash` | бюджет кэша, 0–2048 МиБ | 32 |
| `clearcache` | `Clear Hash` | очистить кэш | — |
| `threat N` | `Threat Weight` | вес локального риска, 0–300% | 100 |
| `chain N` | `Chain Weight` | вес прогноза, 0–100% | 40 |
| `variants N` | `MultiPV` | число показанных вариантов | 3 / 1 |

`Chain Weight 0` отключает влияние дальнего прогноза; текущий мат и текущая ничья остаются исходами по правилам. `MultiPV` влияет только на вывод. При полном расчёте без временных/узловых ограничений результат не зависит от числа потоков и включения кэша. При ограничении времени быстродействие влияет на достигнутые фазы и поэтому может менять ход.

UCI поддерживает `stop`, `isready`, `ucinewgame`, ограничения `nodes`, часы сторон, `Move Overhead`, `UCI_LimitStrength`, `UCI_Elo` и `UCI_AnalyseMode`. Значение `UCI_Elo` — регулятор вычислительного бюджета, не измеренный рейтинг. `go infinite` использует предел 128; после достижения внутреннего предела ожидает `stop`.

Старые `Mate Defense`, `Mate Attack`, консольная команда `mate` и параметры `MateDef`, `MateAtt`, `MThreat`, `Trap`, `CheckGain`, старые позиционные `PAdv1`, `PBPair` и остальные параметры этой группы, `Dev`, `PassFree`, `PassSupp`, `PassKing` удалены. Неизвестные UCI-опции игнорируются. Остальные коэффициенты доступны через `setoption name W:<имя> value <число>`; перечень и диапазоны находятся в `src/params.rs`. NaN, бесконечность и значения вне диапазона отклоняются. Смена коэффициента автоматически инвалидирует кэш.

## Модель поля

Фигуры излучают по своей геометрии. Луч затухает как `0.93^distance`, встречная фигура поглощает прямую компоненту; ослабленная компонента описывает давление за преградой. Связки ограничивают допустимые источники атак. Гауссовы функции задают центр и окрестности королей, насыщение давления имеет вид `x/(x+0.8)`.

Энергия состоит из суммарного заряда, контроля пространства, давления у королей, поддержки источников, направленного пешечного потока и охвата поля. Для всех некоролевских источников действует общий потенциал:

```text
Relief × sqrt(100/mass) × centre
+ Cohesion × ln(1 + mass/100) × saturation(support)
```

Пешечный поток к превращению:

```text
Transport × (mass_queen − mass_pawn) × 0.55^distance × arrival
```

`arrival` учитывает занятость пути, давление волн на каждой клетке, расстояния королей и поддержку собственного короля. Заблокированный путь не переносит заряд. Особое состояние пешки здесь обусловлено правилом превращения, а не списком шахматных бонусов. В окончаниях геометрия безопасной области короля создаёт градиент к мату.

Размен — последовательный локальный перенос массы. После каждого переноса геометрия источников, открывшиеся лучи, связки и безопасность короля проверяются заново. Вступление следующего источника определяется ближайшей компенсацией; результат не сворачивается обратно по minimax. Такая локальная модель остаётся приближённой и не доказывает сложную комбинацию.

Прежние стопки максимум из шести атакующих удалены. Поле хранит снимок геометрии; передняя фигура батареи должна реально освободить луч, а король не считается защитником клетки, на которую он не может законно взять. Учитываются превращения и снятие настоящей жертвы при взятии на проходе.

## Траектории и защита от зевков

1. Все легальные корневые ходы получают оценку поля. Ближайшая потеря считается только по реальным легальным захватам соперника. Проверяется мат в один реальный ход. Встречное давление ослабляется при собственной угрозе потери материала.
2. Первые ответы образуют суперпозицию: до `ReplyK` ответов, амплитуда `exp((value − peak)/ReplyTau)`. По умолчанию 3 и 60. Амплитуды ниже 0.02 отбрасываются.
3. Дальше каждая траектория следует локальному градиенту энергии действующей стороны. Нет обратного выбора лучшего/худшего потомка. Концентрация нормированных амплитуд `Σp²` уменьшает достоверность при неоднозначном продолжении: `confidence *= 0.94 + 0.06×Σp²`.
4. Оценка сглаживает последовательные пары фаз с коэффициентом 0.35. Благоприятные далёкие события дополнительно умножаются на достоверность. Риск разных первых ответов учитывается как среднее минус половина нижнего полустандартного отклонения. Неприятный ответ меньше растворяется в среднем.
5. После первичной оценки явно слабые тихие траектории вне первых восьми и далее 250 сотых пешки от лидера не удлиняются; шахи, взятия, превращения и ответы на шах пока сохраняются. После третьей фазы перестают удлиняться корневые варианты вне первых восьми и дальше 250 сотых пешки от лидера. Они сохраняют уже полученную оценку. Циклы и достоверность ниже 0.20 тоже останавливают траекторию. Это эвристический отбор, он может пропустить важное продолжение.
6. Текущий исход по правилам достоверен. Мат или ничья в далёкой траектории — прогноз с весом и достоверностью. Предсказанный мат выводится числовой оценкой, без ложного UCI `mate N`; найденный последний матующий ход включён в линию. Поэтому показанная линия иногда на один полуход длиннее очередной фазы распространения.

Новая длина по умолчанию — 16 вместо 5, предел — 128 вместо 60. Циклические/неуверенные цепочки могут закончиться раньше. В MultiPV выводится фактическая длина каждой линии; это не глубина полного дерева.

Лимиты проверяются между оценками ходов. Незавершённая фаза продолжения не подменяет последнюю полную. При крайне коротком лимите в корне используются только полностью оценённые ходы; если не оценён ни один, возвращается легальный запасной ход с глубиной 0. Такой режим не гарантирует тактической надёжности.

## Память и исправления правил

`src/cache.rs` хранит только локальную оценку позиции, без результатов цепочек, глубин или границ поиска. Четыре записи на корзину уменьшают вытеснение при совпадении индекса. Версионная метка и атомарные снимки исключают чтение смешанной пары ключ/значение при гонке. Служебные поля входят в бюджет памяти; фактический размер может быть меньше запрошенного из-за округления.

Память партии и текущий план сохранены. Кэш не хранит контекст повторений: он проверяется отдельно по истории. Хэш включает поле взятия на проходе только при наличии легального взятия. Исправлены авария на недостоверном поле en passant в FEN, переполнение счётчиков, распознавание мёртвой позиции со слонами одного цвета полей и потеря `stop` в очереди UCI-команд.

## Проверки

```sh
cargo test
cargo run --release -- selftest
python tests/uci_protocol.py target/release/wavechess
```

Для независимых проверок установите **только в тестовое окружение** `python-chess`:

```sh
python -m venv .venv
# Linux/macOS:
. .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install python-chess
python tests/rules_oracle.py
python tests/compare.py --engine baseline=/path/to/2.1 --engine revised=/path/to/2.2 --output comparison.json
python tests/match.py --baseline /path/to/2.1 --revised /path/to/2.2 --output match.json
```

Фактические результаты, условия замеров и ограничения выводов — в `CHANGES_RU.md` и `reports/`. Небольшой тактический набор и короткий матч не устанавливают рейтинг Elo. Глубокие комбинации по-прежнему могут быть пропущены: отказ от рекурсивного доказателя мата означает, что дальние маты не доказываются.
