# WaveChess 4

Экспериментальный движок на Rust: геометрическое поле, перенос массы и прямые волновые траектории. Без minimax, negamax, alpha-beta, поиска покоя, нейросети и дебютной книги. Stockfish используется **только отдельным тестовым процессом**; движок не вызывает его и не заимствует его оценки.

Правила шахмат, генерация легальных ходов, UCI и кэш локального поля сохранены. Дальняя линия — прогноз ограниченной модели, а не доказательство выигрыша. Уверенность модели не является вероятностью победы.

Версия 4 разделяет прямое поле и давление за преградами, переносит ансамбль
ответов на последующие фазы и учитывает риск через экспоненциальную полезность.
Постоянный пул работников и общий кэш локальных фактов переиспользуются между
ходами. Результаты, ограничения и условия измерений: [отчёт v4](reports/v4/ANALYSIS_RU.md).

## Скачать и запустить

Ветка `wavechess-4` содержит версию 4; `wavechess-3.2` сохраняет 3.2; `wave-engine-v3` сохраняет 3.0. Ветка `baseline-2.2` сохраняет исходники из присланного архива без изменения алгоритма. Вкладка **Actions → build → успешный запуск → Artifacts** содержит сборки Windows и Linux. Нужна авторизация в GitHub для скачивания артефактов частного репозитория.

Сборка требует стабильного Rust. Rayon используется только для постоянного пула
работников и распределения задач; шахматная математика остаётся в этом репозитории.
Версии зависимостей зафиксированы в Cargo.lock:

```sh
cargo build --release --locked
cargo test --release
cargo run --release -- selftest
cargo run --release -- play
```

Windows: `build_windows.bat`, затем `play.bat`. Linux/macOS: `sh build.sh`. Для шахматной оболочки запускайте бинарный файл с аргументом `uci`; при перенаправленном stdin UCI включается автоматически. Старые бинарные файлы из архива не выдаются за новую версию.

## Что изменилось в 4

- Прямая волна останавливается на первой преграде. Ослабленный поток за ней
  хранится отдельно; он не защищает фигуры и не создаёт непосредственной
  атаки на короля. В контроль пространства входит только 20% такого потока.
- Альтернативы ответа соперника распространяются на каждом его ходе внутри
  ограниченного ансамбля. Перенос сохраняет массу; компрессия сохраняет
  опаснейшую наблюдённую траекторию с её собственным весом и распределяет
  оставшуюся массу систематической выборкой.
- Итог ансамбля — конечная экспоненциальная мера риска. Редкий опасный ответ
  получает больше влияния, чем при арифметическом усреднении. Обратной
  minimax/negamax-свёртки, alpha-beta или MCTS нет.
- Rayon сохраняет работников между фазами и ходами; свободные работники
  помогают рассчитывать ходы внутри других волн. Счётчики разделены по
  работникам и выровнены по строкам кэша, уменьшая общие атомарные записи.
- Хэш сохраняет локальную энергию и факты мата/пата/недостатка материала.
  Счётчик 50 ходов и повторения проверяются отдельно при каждом обращении.
- Завершённая фаза всей группы публикуется целиком. Незавершённое разветвление
  при дедлайне не смешивает старые и новые вероятности внутри одного корня.

Больше доступного времени/CPU позволяет завершать больше фаз; больший Hash
помогает, когда рабочее множество перестаёт помещаться в меньший кэш.
Это не гарантирует монотонного роста силы на каждой позиции. `depth` означает
длину прямого прогноза и не сопоставим с глубиной Stockfish.

## Сохранённые возможности 3.x

- Предел цепочки — 256 полуходов, обычный предел — 48. Низкая уверенность сама по себе больше не останавливает расчёт. Реальный мат, пат, правило 50 ходов и троекратное повторение завершают траекторию.
- Время распределяется между корневыми волнами. При дедлайне сохраняются целиком законченные группы ответов; незаконченная группа сохраняет предыдущую фазу. Длина вывода — фактическая длина показанной линии, а не глубина полного дерева.
- Неоднозначность продолжения учитывается в доверии к прогнозу. Ранний провал энергии не исчезает бесследно после воображаемого восстановления в дальней линии.
- Дебюты разнообразятся выбором по нормированным амплитудам внутри узкого окна оценок. Случайность не прибавляется к оценке хода. Нет книги или списка «правильных» дебютов. Разнообразие отключается в анализе, при шахе и после шестого полного хода.
- Память сохраняет альтернативные ответы соперника. Обычное обновление UCI-позиции не стирает историю. Если оболочка присылает только FEN, движок умеет восстановить один или два легальных хода от известной позиции; произвольный несвязанный FEN начинает новый контекст.
- Команды `save` и `load` сохраняют/восстанавливают историю, повторения, планы и фазу разнообразия между запусками. Повреждённый журнал не заменяет текущую партию. Сохранение выполняется по команде пользователя, не автоматически.
- В консоли и UCI можно увидеть ближайшую энергию, итоговый прогноз, уверенность модели и число траекторий. Карта поля и подробное разложение энергии доступны через `wave`.

## Настройки

| Консоль | UCI | Значение |
|---|---|---|
| `depth 48` | `go depth 48` | максимальная длина цепочки, 1–256 |
| `time 3` | `go movetime 3000` | время на ход |
| `threads 4` | `Threads` | рабочие потоки |
| `cache 64` | `Hash` | кэш локальных энергий, МиБ |
| `width 8` | `Wave Width` | число основных корневых волн, 1–32 |
| `chain 40` | `Chain Weight` | вес прогноза, 0–100%; 0 оставляет ближайшую оценку |
| `threat 130` | `Threat Weight` | вес локального потока потерь |
| `variety 20` | `Opening Variety` | окно дебютных оценок, сотые пешки; 0 отключает разнообразие |
| `seed 42` | `Random Seed` | воспроизводимая последовательность партий; 0 — seed от времени запуска |
| `variants 3` | `MultiPV` | количество показываемых корневых вариантов |
| — | `W:Particles` | целевой предел частиц на корень: 8, диапазон 1–64; минимум фактически `W:ReplyK` |
| — | `W:RiskTau` | масштаб экспоненциального риска: 120 сотых пешки; 0 включает прежнее усреднение |
| — | `W:Spectral` | вес вспомогательного FWHT, 0–50 сотых пешки; 16 по умолчанию, 0 отключает |
| `clearcache` | `Clear Hash` | очистить кэш; история партии сохраняется |
| `memory` | `memory` | история/план; в UCI краткий диагностический ответ |
| `save game.wave` | — | сохранить партию с планами |
| `load game.wave` | — | восстановить партию с планами |

`new` / `ucinewgame` начинают новую партию и очищают её историю. `undo` отменяет ход и устаревший план. Одинаковые seed, позиции и число новых партий дают одинаковое разнообразие при полном расчёте. Ограничение по времени зависит от производительности машины; для воспроизводимого сравнения используйте фиксированный предел глубины/узлов и `Opening Variety=0`.

`UCI_Elo` регулирует бюджет вычислений и **не обозначает измеренный рейтинг**. `UCI_AnalyseMode` отключает разнообразие и ограничение силы. `W:*` открывает коэффициенты поля; NaN, бесконечности и значения за допустимыми диапазонами отвергаются.

## Математика

Доска — решётка 8×8. Источники излучают вдоль разрешённых геометрических направлений. Прямая волна поглощается первой фигурой; ослабленная компонента моделирует давление за преградой. У луча затухание `0.93^(distance−1)` (первая соседняя клетка: distance=1); насыщение поля — `x/(x+0.8)`. Центр и окрестности королей описываются гауссовыми потенциалами.

Энергия складывается из массы, контроля, давления на короля, поддержки источников, подвижности и потока пешки к границе превращения. Общий потенциал некоролевского источника:

```text
Relief × sqrt(100/mass) × centre
+ Cohesion × ln(1 + mass/100) × saturation(support)
```

Перенос пешечного заряда: `Transport × (mass_queen − mass_pawn) × 0.55^distance × arrival`. Занятый путь поглощает поток; давление и расстояния королей меняют `arrival`. Размен моделируется прямой последовательностью допустимых переносов массы, без обратной минимаксной свёртки.

Все корневые ходы получают локальную оценку, включающую реальные допустимые
взятия соперника, превращения и мат в один ход. На фазах соперника до
`W:ReplyK` ответов образуют распределение `p ∝ exp((energy − peak)/ReplyTau)`.
Его масса нормируется внутри продолжений родительской частицы. На своей фазе
частица следует локальному градиенту. Это ограниченная модель политики, а не
перебор всех вариантов против наилучшей защиты.

При превышении `max(ReplyK, Particles)` сохраняется наиболее неблагоприятная
наблюдённая траектория с её исходной массой; остальные представлены
детерминированной систематической выборкой с сохранением суммарной массы.
Корни отстающие более чем на 250 сотых пешки вне Wave Width могут прекратить
развитие. Уверенность — эвристический вес фаз, не вероятность выигрыша.

При `RiskTau > 0` итог корня вычисляется устойчивым log-sum-exp:

```text
S = -RiskTau × log(sum_i(p_i × exp(-S_i / RiskTau)))
```

`S_i` учитывает локальную энергию, сглаженные фазы, провалы энергии и
ограниченную полезность предполагаемого мата. Конечный RiskTau сохраняет
вклад всех частиц; оценки не сворачиваются назад по дереву. Мат в дальней
траектории выводится как числовой прогноз, а не доказанный `mate N`.
Не вошедший в ансамбль ответ всё ещё может опровергнуть прогноз.

Кэш содержит локальные значения с полным 64-битным ключом позиции; Draw и Mate
имеют отдельные маркеры. Повторения и правило 50 ходов не кэшируются.
Мат имеет приоритет над достижением 100 полуходов. Зависимые от параметров
значения сбрасываются при изменении параметров. При отключённом хэше
математика завершённого расчёта сохраняется.

## Проверки и матчи

Быстрая программа измерения силы (один матч за раз, без графического интерфейса):

```sh
python -m pip install -r tests/requirements.txt
python tests/quick_elo.py --engine target/release/wavechess --stockfish /path/to/stockfish19 --elos 1320,1520,1720,1920 --pairs 8 --movetime-ms 60 --output ladder.json
python tests/quick_elo.py --engine target/release/wavechess --reference /path/to/wavechess3.0 --pairs 16 --movetime-ms 120 --output versions.json
python tests/quick_elo.py --engine target/release/wavechess --reference target/release/wavechess --opponent-options '{"W:Spectral":0}' --pairs 16 --movetime-ms 60 --output fwht.json
```

Параметры Stockfish проверяются по реальному UCI-диапазону. У каждой начальной
позиции меняются цвета. JSON содержит имена, SHA-256, настройки, результаты,
время и интервалы оценки; рядом сохраняется PGN. Существующий файл результатов
не перезаписывается. Прерванные партии не становятся ничьими; рейтинг использует
только полностью законченные пары. Повторы одного дебюта на разных уровнях
объединяются при оценке погрешности. Быстрый результат — условный ориентир на
шкале `UCI_Elo` Stockfish при данном контроле, не рейтинг FIDE или chess.com.
Увеличение числа открытий и времени повышает полезность проверки; один короткий
матч не доказывает прирост силы.

```sh
cargo test --release
cargo run --release -- selftest
python tests/uci_protocol.py target/release/wavechess
python -m venv .venv
# Активируйте .venv в своей оболочке.
python -m pip install -r tests/requirements.txt
python tests/rules_oracle.py
python tests/compare.py --engine baseline=/path/to/2.2 --engine revised=/path/to/3.0 --depth 8 --movetime-ms 250 --output comparison.json
python tests/arena.py --baseline /path/to/2.2 --revised /path/to/3.0 --games 16 --movetime-ms 150 --output match.json
```

`tests/arena.py` сохраняет PGN, SHA-256 бинарных файлов, параметры, окончание каждой партии и фактическую длину линий. `--suite start` играет с начальной позиции; `--suite conversion` **даёт новой версии заранее выигрышную позицию** и проверяет только доведение перевеса. Незавершённые партии не засчитываются как ничьи. Оценочного присуждения побед нет. Цвета меняются в каждой паре.

Фактические результаты и ограничения — в [CHANGES_RU.md](CHANGES_RU.md) и [reports/v3](reports/v3). Старые отчёты сохранены отдельно в [reports/baseline-2.2](reports/baseline-2.2). Несколько побед над прошлой версией или Stockfish из выигрышного окончания не доказывают рост Elo и не означают превосходство над полным Stockfish с равного старта.

Исторический итог контроля 3.0 против 2.2: **7 побед, 7 поражений, 2 ничьи** при 250 мс на ход. Подтверждённого роста Elo нет.

Дополнительные проверки v4 (запускайте последовательно, без других матчей):

```sh
python tests/scaling.py --engine target/release/wavechess --output scaling.json
python tests/tactical_audit.py --engine old=/path/to/3.2 --engine new=target/release/wavechess --stockfish /path/to/stockfish19 --pgn reports/v3.1/ladder-combined.pgn --output audit.json
python tests/validate_match.py ladder.json versions.json
```

Замеры повторной позиции с прогретым хэшем показывают верхнюю границу пользы
повторного использования; это не оценка Elo. Для более серьёзной рейтинговой
оценки нужны значительно больше независимых дебютов и более длинный контроль.
